IMPORTANT: CURRENT TPM CONFIGURATION
======================================================================

The TPM/LUKS system recently stopped automatically unlocking after a BIOS
USB-boot setting was changed.

The failure was diagnosed as:

    TPM policy does not match current system state

The TPM itself was NOT cleared/reset.

The old TPM enrollment used:

- direct PCR binding:
    PCR 7

- signed PCR policy:
    PCR 11

- PCR bank:
    SHA-256

- signed policy reference:
    initrd

- TPM SRK:
    enabled

- TPM PIN:
    disabled

- PCRLock:
    disabled

The existing public key embedded in the LUKS TPM token was extracted and
reused.

Before changing the TPM enrollment, a LUKS header backup was created:

    /home/user/Projects/security-center/docs/recovery-backups/luks-header-before-tpm-reenroll.img

Permissions:

    root:root
    0600

The TPM enrollment was repaired with approximately:

    systemd-cryptenroll \
        --wipe-slot=tpm2 \
        --tpm2-device=auto \
        --tpm2-pcrs=7 \
        --tpm2-public-key=<recovered existing TPM PCR public key> \
        --tpm2-public-key-pcrs=11 \
        --tpm2-public-key-policyref=initrd \
        /dev/nvme0n1p2

Result:

    New TPM2 token enrolled as key slot 2.
    Wiped slot 1.

CURRENT LUKS KEY SLOTS:

    keyslot 0
        normal manual LUKS passphrase
        Argon2id

    keyslot 2
        TPM2 automatic unlock

Current TPM token contains:

    tpm2-hash-pcrs:   7
    tpm2-pcr-bank:    sha256
    tpm2-pubkey-ref:  initrd
    tpm2-pubkey-pcrs: 11
    tpm2-primary-alg: rsa
    tpm2-pin:         false
    tpm2-pcrlock:     false
    tpm2-srk:         true

Secure Boot currently reports:

    Secure Boot: enabled (user)

TPM auto-unlock now WORKS again.

IMPORTANT:

DO NOT:
- clear/reset the TPM
- delete keyslot 0
- remove the manual LUKS passphrase fallback
- casually alter PCR7/PCR11 policy
- regenerate the TPM public key without understanding the signed PCR11 setup

======================================================================

Future feature:

TPM automatic LUKS unlock should ONLY be allowed if the machine boots with an

    unknown USB device

    unknown HID devices

    unexpected boot media

    DO NOT BRICK THE LAPTOP

Instead:

    TPM automatic unlock is unavailable
    manual LUKS passphrase must be entered

Once Linux is fully booted, devices may be connected according to normal
postboot USBGuard/security policy.

Do NOT merely allow every device claiming to be a mouse.

Where useful, identify trusted devices by combinations of:

    VID:PID
    serial
    USB interfaces
    physical port
    device topology

The preboot device checker should run in initramfs BEFORE TPM-backed root
unlock.

    +
    valid normal user/root authentication

On that next reboot:

- normal TPM automatic unlock
- normal PCR7/PCR11 behavior
- normal preboot device policy
- normal trusted-device exceptions
- normal USBGuard policy
- normal firewall policy
- normal desktop/login behavior
- normal Security Center state

Think of distress mode as a STATE MACHINE:

    NORMAL
      |

If restoration fails:

Do not fail open.
